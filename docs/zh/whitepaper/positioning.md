# 项目定位

## Hetero-Paged-Infer 是什么

Hetero-Paged-Infer 是一个“适合学习、也具备工程形状”的推理引擎项目。它目前还不是完整 CUDA 生产栈，但已经把真正关键的结构决策——内存管理、调度、服务边界、测试策略、未来扩展点——做成了可以讲清楚的系统。

更具体地说，项目已经有真实的 `InferenceEngine` 边界、带队列与内存压力规则的调度器、分页式 KV Cache 管理器，以及可审阅的文档与测试面。它现在的价值不是“已经跑赢成熟推理框架”，而是“已经能把核心架构决策以工程化方式落到代码里，并且能被逐项讨论”。

## 它不是什么

1. 不是当前阶段就以跑分取胜的项目
2. 不是直接替代 vLLM / TensorRT-LLM 的成熟产品
3. 不是只有 CLI 没有架构故事的玩具 Demo

这些“它不是什么”非常重要，因为它决定了读者应该如何阅读这份白皮书。文档里提到吞吐、内存效率、未来 GPU 路线时，会明确区分三件事：仓库今天已经证明了什么、接口与测试已经表达了什么、以及哪些部分必须等真实 CUDA kernel 落地后才有资格谈生产可信度。

## 为什么这种定位有意义

成熟推理系统最终要同时回答 kernel、调度、内存行为和运行时边界的问题。很多教学项目会解释概念，但不会把它们真正组织成一个系统；很多产品页面则反过来，只给结论，不展示结构。

Hetero-Paged-Infer 选择站在两者之间：它已经具体到可以被拆解、被审阅、被扩展，但也足够诚实，不会把尚未完成的 CUDA 生产能力包装成既成事实。这让它适合作为“现代 LLM Serving 架构到底是如何被组织起来”的研究型样本，而不是伪装成已经交付最终生产能力的宣传页面。

## 建议如何阅读本白皮书

- 把它看作一份关于“为什么分页式 KV 管理要和连续批处理一起设计”的架构论证；
- 把它看作一份说明仓库当前到底实现到了哪里的证据说明；
- 把它看作一份说明未来要补哪些关键能力，才有资格谈生产 GPU 可信度的路线图。
