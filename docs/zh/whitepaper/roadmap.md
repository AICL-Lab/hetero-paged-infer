# 路线图

## 近期可信度建设

第一优先级不是增加更多宣传语，而是补强证据链。这包括让架构文档与代码继续保持一致，在调度器与 KV Cache 不变量最关键的位置补足正确性测试，以及在真实 GPU 执行存在后，把 benchmark 方法学写清楚。近期目标是尽量消除“设计过”“实现了”“测量过”三者之间的歧义。

## Serving / 运行时工作

当前项目已经有清晰的引擎边界，但生产 Serving 需要的远不止一个单进程主循环。接下来的重点应包括：请求准入策略、取消与超时语义、更丰富的指标、更加清晰的失败面，以及围绕配置和部署的运行时体验。这一层决定了强核心是否能变成可运维的服务。

## GPU Kernel 工作

真正的生产可信度，最终取决于能否把 mock executor 替换为真实 CUDA 路径。这部分工作包括：分页注意力 kernel、decode 路径优化、在确实能降低 launch overhead 时使用 CUDA graph capture，以及围绕真实批次形态开展严格 benchmark。它是最关键的未来工作，因为它把“架构意图”变成“硬件支撑的证据”。

## 研究级扩展

当核心路径足够可信之后，项目就可以探索更具研究性的扩展：speculative decoding、序列分支、更复杂的内存复用策略、异构执行器后端，或面向不同工作负载类别的调度策略。它们之所以值得做，是因为当前代码已经把这些扩展未来应该插入的位置暴露出来了。

## 明确保持在范围外的事项

Hetero-Paged-Infer 不应该试图一次性变成“什么都做”的系统。近期工作应刻意避免：在 CUDA 后端落地前就参与成熟系统 benchmark 口水战、过早宣称支持所有模型、或者把大规模分布式编排一并打包进当前目标里。相比扩张叙事，守住一个聚焦的 thesis——清晰架构、明确边界、诚实证据——更能提升项目可信度。
