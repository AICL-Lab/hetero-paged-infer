# 技术白皮书

这份白皮书是理解 Hetero-Paged-Infer 的入口：它解释项目为什么存在、当前到底证明了什么，以及哪些生产可信度仍然依赖未来 GPU 路径的落地。

Hetero-Paged-Infer 是一个以 Rust 为核心语言的现代 LLM Serving 架构探索：分页式 KV Cache、连续批处理、内存压力感知调度，以及面向生产的 API 形态。

## 白皮书结构

本章节按四页结构展开：

1. **概览**（当前页）——说明问题背景、整份白皮书的 thesis，以及推荐的阅读方式。
2. [**项目定位**](./positioning) ——解释这个项目是什么、不是什么，以及这种定位为什么重要。
3. [**证据与边界**](./proof) ——区分已经实现和验证的事实、继承自文献的论点，以及当前仍然存在的边界。
4. [**路线图**](./roadmap) ——说明还需要补哪些工作，才能把架构意图进一步变成生产可信度。

## 为什么需要这份白皮书

很多 LLM Serving 讨论会把架构、实现和 benchmark 结论混在一起。这份白皮书刻意把它们拆开：它描述项目今天的真实状态，指出仓库已经具备哪些证据支撑，并明确说明哪些判断仍然要等真实 CUDA 后端落地后才更有资格成立。

## 建议阅读顺序

如果你是第一次了解这个项目，建议按顺序阅读：

- 先从当前页理解整体背景；
- 再看[项目定位](./positioning)理解项目 thesis；
- 接着阅读[证据与边界](./proof)把握证据边界；
- 最后看[路线图](./roadmap)了解后续重点工作。
